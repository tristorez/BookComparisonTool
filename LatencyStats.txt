1. FANDUEL: WHAT THE POLL INTERVAL COSTS
----------------------------------------------------------------------------------------------------
Reproduce:   npx tsx scripts/poll-sweep.ts
Data:        test/fixtures/fd-live-2026-10-19.jsonl.gz, recorded on Box A (us-east-2), 70 in-play markets,
             178 s, 696 PIR push frames and 179 SMP polls at 1 s.

Method
  - The same real price moves are replayed through different channel setups. Polls are thinned to every
    2nd or 5th one, at every phase, and the phases are pooled.
  - Reference = the earliest time any channel in the full recording (push + every 1 s poll) showed each
    price state of a market: 773 states.
  - Delay = when a config first showed a state minus the reference time. A state the config does not show
    within 5 s of the reference is "missed" (a transient the slower channel skipped, or shown only as a
    later recurrence of the same price).

Result (delay vs reference, ms)

  config                          mean    p50    p90    p99    max   missed
  push only                        112      0    362    570   1219    10.5%
  poll only 1 s                    147      0    464    621   1234     2.2%
  poll only 2 s                    582    428   1343   1600   3309     7.4%
  poll only 5 s  (FD's site)      1824   1993   4004   4530   4783    16.1%
  push + poll 1 s (shipped)          0      0      0      0      0     0.0%   <- reference by construction
  push + poll 2 s                   50      0    235    501   1000     0.7%
  push + poll 5 s                   81      0    322    528   1219     1.1%

What it says
  - Polling alone is expensive. FD's own 5 s cadence is ~1.8 s late on average (p90 4.0 s) and misses 16%
    of states entirely. Our 1 s poll alone is 147 ms behind on average.
  - Push alone is 112 ms behind on average, p90 362 ms, and still misses 10.5% of states that only a poll
    caught.
  - The combination is what gets to zero: each channel covers the other's gaps. Dropping the poll from
    1 s to 2 s costs 50 ms on average (p90 235 ms); to 5 s costs 81 ms (p90 322 ms).
  - So the 1 s poll buys about 50-80 ms of mean latency and 235-322 ms at p90, against the next-slower
    options, on top of push. It costs one ~3.4 KB gzipped request per second per box.

Caveats (read before quoting)
  - The reference is the shipped config, so "push + poll 1 s" is 0 by construction. The rows to compare are
    the others, relative to it. It is not absolute book -> screen latency.
  - One 3-minute session, 70 markets, 773 states. Treat the p99 and max columns as indicative only.
  - 0.5 s polling cannot be replayed (no polls between the 1 s ones). The two-box interleave (+0.5 s on
    Box B) is the only 0.5 s data and has not been measured separately.
  - The replay assumes polls do not change what push delivers. True for the recording; a live A/B at
    different intervals would confirm it.
  - FD's book timestamp is whole seconds, so this file measures relative arrival, not time since the
    sportsbook changed the price.
